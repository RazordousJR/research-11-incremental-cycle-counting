# Literature audit, exact dynamic triangle counting

Date of audit: 2026-11-01. Cut-off: 1 November 2026, which covers the prompt's 7 October cut-off and the 24
days after it. That extra window held the closest paper found, so it mattered. Task M1A01.

## Method and limits

Sources used: web search; arXiv API title queries (`scr/arxiv.tsv` in the session scratchpad, 32 records
since 2022); OpenAlex API (371 records since 2022); forward reading of the bibliography of Hanauer et al.
2026; GitHub API on the official repositories.

**Limits, stated plainly.**
- DBLP was not screened. Its API sat behind a bot check, and bot checks are not bypassed here.
- OpenAlex and arXiv are not complete for proceedings of 2026.
- IEEE Xplore returned no abstract text. EDTC and DYTC were read through the OpenAlex abstract only, and
  EDTC's abstract was cut off in the output.
- The "Read" column says how far each source was read. Abstract-only rows are not evidence about method
  detail.
- Citation details below were taken from the source named in the link. They have not yet been turned into
  a checked `.bib`.

## Decisions the audit forces

1. **The exactly-once proof is required by the PI and is not a contribution.** Rows 2, 3 and 7 already have
   it in three forms.
2. **"Affected-neighbourhood indexing" is rejected as the contribution for triangles.** Row 1 measured
   scanning ahead of every auxiliary structure on total time, across a wider benchmark than this project
   could build. Row 2 shows the index pays only on graphs with extreme hubs.
3. **What stays open.** No source read here studies how to share work between the updates of one batch in
   a scanning algorithm. Row 1 is single-update. Row 2 uses per-edge work with tables. Row 3 uses per-edge
   merges. This gap is narrow. Rows 8 and 13 could still close it.
4. **The strongest simple baseline is now sequential scanning with lower-degree priority**, not full
   recomputation.

## Correction, 2026-11-01, after the scouts

**Decision 3 above is wrong.** It says no source read studies sharing work between the updates of one batch in a
scanning algorithm. DPTL+ (Yu, Qin, Zhang, Zhang, Lin, ICDE 2021,
[record](https://opus.lib.uts.edu.au/handle/10453/153684)) does: its cover letter states that it builds a bitmap hash
table once for each pivot vertex and outputs each updated triangle exactly once. I read the cover letter and searched
the text. The audit missed it. Scout S6 found it, and I confirmed it at the source.

Other corrections from the scouts, in `docs/literature/scouts/`, not yet each checked at the source:
- Cheetah (TACO 2025) and Gopher (EuroSys 2026) share work between updates for general patterns. Read as abstracts.
- Liu et al. (SPAA 2022) give an arboricity batch bound, so the `O(k lambda)` star bound is not new.
- Eppstein and Spiro wrote their structure for ERGMs, which row 5 undersold.
- HyKernel appears to be static counting.

The Gate 0 verdict does not depend on these. Had DPTL+ been found first, the proposal would have been positioned
against it from the start, and the audit limits above understated the risk of a miss.
